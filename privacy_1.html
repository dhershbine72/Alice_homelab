Privacy policy

What this project touches, and why.

Effective and last updated: September 3, 2026

Who this covers

Alice Homelab is a set of personal automation tools built and operated by a single individual, Andrew, for his own use: a YouTube content pipeline, and a set of personal productivity tools (Google Tasks, Google Calendar, and personal Gmail organization). There are no public users, no sign-up flow, and no accounts other than Andrew's own Google account(s). This policy exists to satisfy Google's OAuth verification requirements and to give a complete, specific account of what each tool does with the account access it requests.

What data is accessed, and why

Each tool authenticates directly against Andrew's own Google account using OAuth 2.0. No tool requests more access than the specific job it does requires:

ScopeUsed for
youtube.uploadUploading generated videos and Shorts to Andrew's own YouTube channels.
youtube / youtube.force-sslSetting titles, descriptions, thumbnails, and playlists on uploaded videos; reading channel identity to confirm the correct channel is being written to.
tasksReading, adding, and completing items in Andrew's own Google Tasks lists.
calendarReading and, for a planned feature not yet built, creating or modifying events on Andrew's own Google Calendar.
gmail.modifyReading, labeling, and archiving messages in Andrew's own personal Gmail inbox for automated organization. Never used to send mail, delete mail permanently, or change account settings.

No scope requesting access to anyone else's account, video, comments, analytics, email, tasks, or calendar is ever requested, and no tool acts on any account other than Andrew's own. This project does not read, collect, or process data belonging to viewers, subscribers, contacts, or any other third party.

How the data is used

YouTube pipeline

  • Publishes finished video files (narration, generated visuals, captions) that the pipeline itself produced, to Andrew's own channels.
  • Sets metadata — title, description, thumbnail, playlist assignment — on those uploads.
  • Periodically checks that its own stored access token is still valid, so a dead token can be caught and fixed quickly.

Tasks & Calendar

  • Reads Andrew's task lists so a personal assistant tool can surface or act on them.
  • Adds and completes tasks on Andrew's behalf when he asks for that.
  • Reads calendar events for the same purpose; event creation/editing is a planned but not-yet-built feature.

Gmail organization

  • Reads incoming mail to classify it.
  • Applies labels and archives messages according to rules Andrew has set up.
  • Does not send email, does not permanently delete email, and does not read data from any mailbox other than Andrew's own.

This project does not use any of this data for advertising, does not build behavioral or personality profiles, and does not use Google user data to train any generative AI/ML model.

Where data is stored, and who it's shared with

OAuth tokens and any data pulled via these APIs are stored on private, self-hosted infrastructure that Andrew owns and controls, on his own home network. Nothing is sent to a third-party analytics service, advertising network, or data broker. No data is sold, rented, or shared with any other person, company, or service. The only "sharing" that occurs is the intentional, direct result of the tool's function — for example, a video the pipeline uploads becomes publicly viewable on YouTube, the same as any other video a person publishes there.

Data retention and deletion

Access and refresh tokens are kept only as long as the relevant tool is actively in use, and are replaced whenever Andrew re-authorizes the app. Email, task, and calendar content accessed via the API is processed in-memory for the specific action being performed (labeling, uploading, reading) and is not separately archived beyond what Google's own services already retain in Andrew's account.

Andrew can revoke this project's access to any or all of these scopes at any time from his Google Account's third-party access settings, which immediately invalidates all stored tokens for that app.

Security

Credentials are stored on infrastructure Andrew personally controls and are not accessible to any other person or third-party service. This project has no public-facing login, API, or web service that accepts external requests — it runs entirely as scheduled, private automation.

Children's privacy

This project is not directed at children and is not a public service of any kind — it is a private automation tool with a single adult operator and no other users.

Changes to this policy

If what this project accesses or does with that access changes, this page will be updated and the "last updated" date above will change accordingly.
